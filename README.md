# puppeteer-project — парсер OBD Memorial через Edge CDP

Парсер карточек персон сайта **ОБД Мемориал** ([obd-memorial.ru](https://obd-memorial.ru)).

Работает **не** через безголовый Chrome, а через подключение к уже запущенному **Microsoft Edge** по протоколу **CDP** (remote debugging). Edge запускается отдельным процессом.

## Требования

- Windows 10 (рабочий ПК)
- Node.js **24.5.0** (зафиксировано в `.nvmrc`)
- Microsoft Edge
- PowerShell 7+ (`pwsh`)

## Установка

```powershell
cd C:\путь\к\puppeteer-project
$env:PUPPETEER_SKIP_DOWNLOAD="true"
npm install
```

> Puppeteer используется только как CDP-клиент (без скачивания своего браузера).

## Запуск

### 1. Поднять Edge с CDP

```powershell
pwsh scripts\RunEdgeOBD.ps1
```

Скрипт:
- ищет `msedge.exe` в стандартных путях;
- создаёт/использует профиль `user_01` **вне репозитория**;
- чистит только кэши;
- запускает Edge с `--remote-debugging-port=9226`;
- открывает obd-memorial.ru (сессия/авторизация сохраняется).

### 2. Проверить входные файлы (контроль дублей)

```powershell
node scripts/check-input.js                  # все файлы в data/raw/
node scripts/check-input.js --file=имя.txt   # один файл
```

Покажет: всего строк, уникальных, дублей внутри файла, сколько уже обработано (журнал + глобальная сумма), сколько новых.

### 3. Запустить парсер

```powershell
node obd-edge.js                 # обработать ВСЕ .txt из data/raw/
node obd-edge.js --input=имя.txt # только указанный файл
node obd-edge.js --dry-run       # только показать, ничего не писать
```

## Входные файлы

- Кладите любые `.txt` в `data/raw/` (имя файла может быть осмысленным, например `links_id_398_сд_03_1942_крым.txt`).
- Формат: по одному URL на строку; строки с `#` — комментарии.
- Жёсткой привязки к имени `input_urls.txt` **нет**.

## Выходные файлы (для каждого входного файла `<имя>`)

```
data/processed/<имя>/
├── <имя>__parser_mem2026.csv     # убит/погиб
├── <имя>__other_mem2026_.csv     # остальные причины
├── <имя>__session.log            # полный лог прогона
├── <имя>__errors.log             # только ошибки
└── <имя>__processed.txt          # журнал обработанных URL (возобновление)
```

## Глобальная сумма

`data/summary/processed_ids.txt` — накопитель id (хвостов адресов) по **всем** файлам. После каждой успешной карточки туда дописывается id. Используется `check-input.js` для контроля: **не ходить повторно за одной карточкой**.

## Задержки

Между запросами — **рандомизированные паузы** (чтобы не походить на бота):
- после загрузки страницы: 3–6 сек;
- между карточками: 3–15 сек.

Парсер рассчитан на фоновую работу.

## Типы карточек

| Тип | Особенности |
|---|---|
| «Информация из документов, уточняющих потери» | есть «Причина выбытия», «Дата выбытия», «Первичное место захоронения» |
| «Информация из списков захоронения» | нет «Причины выбытия»; есть «Дата смерти», «Место захоронения», «Откуда перезахоронен» |

Дата гибели берётся из «Дата выбытия» или «Дата смерти». Захоронение — из «Место захоронения» (fallback — «Первичное место захоронения»).

## Логика разделения «убит/погиб»

1. Причина выбытия содержит «убит» или «погиб» → **killed**.
2. Причина не указана, но есть «Дата смерти» и захоронение (первичное/место) → **killed**.
3. Остальные случаи → **other** (причина/особенности уходят в `notes`).

## Возобновление после краша

Скрипт ведёт журнал `data/processed/<имя>/<имя>__processed.txt` + глобальную сумму. При перезапуске уже обработанные URL/id пропускаются.

## Отчёты

В папке `reports/` хранятся отчёты о работе над проектом (по датам). Формат: контекст → выполнено (коммиты) → ключевые решения → риски → следующие шаги.

- `reports/2026-09-22-report.md` — реорганизация под Edge CDP, гибкий ввод, контроль дублей.

## Структура

```
puppeteer-project/
├── obd-edge.js                 # основной парсер (Edge CDP)
├── scripts/
│   ├── RunEdgeOBD.ps1          # запуск Edge c CDP (user_01, 9226)
│   ├── check-input.js          # контроль входных файлов и дублей
│   ├── launch.json             # VS Code attach к Edge 9226
│   ├── settings.json           # настройки workspace
│   └── extensions.json         # рекомендуемые расширения
├── data/
│   ├── raw/                    # сюда кладёте .txt со списками URL
│   ├── processed/<имя>/        # результаты и логи по каждому файлу
│   └── summary/processed_ids.txt  # глобальная сумма id
├── reports/                    # отчёты о работе (по датам)
├── archive/                    # предыдущая реализация (legacy)
└── .nvmrc                      # фиксация Node 24.5.0
```
