# Резюме сессии: Парсер OBD Memorial

## 🎯 Цель проекта
Автоматический парсинг карточек персон с сайта **ОБД Мемориал** (obd-memorial.ru) через **Puppeteer** (безголовый Chrome) с разделением результатов по причине выбытия.

## 📁 Структура репозитория
```
puppeteer-project/
├── index.js                              # Основной скрипт Puppeteer
├── test.js                               # Тест запуска Puppeteer
├── на_странице_карточки_персоны_OBD_Memorial.txt  # Оригинал F12-скрипта
├── data/
│   ├── raw/
│   │   └── input_urls.txt                # Входной список URL (по одному на строку)
│   ├── processed_urls.txt                # Журнал обработанных URL (для возобновления)
│   └── processed/
│       └── logs/                         # Результаты и логи каждой сессии
│           ├── {YYYY-MM-DD}__parser_mem2026.csv     # убит/погиб
│           ├── {YYYY-MM-DD}__other_mem2026_.csv     # остальные причины
│           ├── {YYYY-MM-DD}__session.log            # полный лог сессии
│           └── {YYYY-MM-DD}__errors.log             # только ошибки
├── README.md
└── SESSION_SUMMARY.md
```

## 🔧 Логика работы index.js

### Вход
- Читает URL из `data/raw/input_urls.txt` (построчно)

### Возобновление после краша
- Скрипт ведёт журнал `data/processed_urls.txt` — туда дописывается каждый успешно обработанный URL
- При запуске скрипт:
  1. Читает `processed_urls.txt` и пропускает уже обработанные URL
  2. Начинает с чистых CSV (без дозагрузки старых данных)
  3. Промежуточное сохранение — каждые 50 записей и при каждой ошибке
- Если скрипт упал — достаточно запустить `node index.js` снова, он продолжит с места остановки

### Обработка каждой карточки
1. Переход по URL через Puppeteer (headless)
2. Пауза **3 сек** после загрузки (для отрисовки DOM)
3. Извлечение данных через `page.evaluate()` — аналог F12-скрипта
4. Пауза **2 сек** перед следующим запросом

### Разделение результатов
```js
const isKilled = cause.includes('убит') || cause.includes('погиб');
```

| Причина выбытия | Файл | notes |
|----------------|------|-------|
| Содержит "убит" или "погиб" | `{дата}__parser_mem2026.csv` | пусто (если нет доп. параметров) |
| Любая другая | `{дата}__other_mem2026_.csv` | причина выбытия |

### Логика поля `notes`
1. Если причина ≠ "убит"/"погиб" → причина в `notes`
2. Если архивные поля пусты (`nomer_fonda`, `nomer_opisi`, `nomer_dela`, `document_type`) → сканируются все `.card_parameter` на странице, неизвестные (не из стандартного списка) добавляются в `notes` (например: `выписка из военкомата: ...`)
3. Оба условия объединяются через ` | `

### Стандартные поля (не попадают в extra-поиск)
Фамилия, Имя, Отчество, Дата рождения, Место рождения, Дата выбытия, Воинское звание, Последнее место службы, Причина выбытия, Первичное место захоронения, Номер фонда/описи/дела, Название источника донесения, Место захоронения, Место призыва

### Выходные CSV
- **UTF-8 с BOM** (для корректной кириллицы)
- Данные **не модифицируются** — только текст как есть
- Если в категории 0 записей — файл не создаётся
- Имена файлов содержат текущую дату запуска (ISO-формат)

### Логирование
- `{дата}__session.log` — дублирует весь вывод в консоль
- `{дата}__errors.log` — только сообщения об ошибках (для анализа и «лечения по смыслам»)

## 📊 Примеры причин выбытия

- **other_mem2026_.csv:** пропал без вести, сдался в плен, эвакуация в госпиталь, умер от ран, и т.д.

## 📌 Важные замечания
- `executablePath` в `puppeteer.launch()` захардкожен под локальный путь пользователя — при смене окружения нужно обновить
- Задержки проставлены для щадящей нагрузки на портал OBD Memorial
- При ошибке на одном URL скрипт не падает — идёт дальше после паузы
- При перезапуске скрипт автоматически продолжает с места остановки (по журналу `processed_urls.txt`)
- Папка `data/processed/logs/` создаётся автоматически при запуске
- Логи сессии и ошибок пишутся в `data/processed/logs/` с датой в имени файла
